# 서버 구동 안내

이 프로젝트는 빌드 도구도, 패키지 의존성도 없다. 파이썬 3.9 이상만 있으면 된다.

---

## 1. 가장 짧은 실행

```bash
cd /home/ec2-user/claude-lab/signal-desk
python3 serve.py
```

기본 포트는 **8137** 이다. 브라우저에서 `http://localhost:8137` 을 열면 된다.

포트를 바꾸려면 인수로 준다.

```bash
python3 serve.py 8080
```

---

## 2. 두 가지 실행 방식의 차이

| 방식 | 명령 | 뉴스·시장 심리 | 지표·수급 |
|---|---|---|---|
| **권장** | `python3 serve.py` | 표시됨 | 표시됨 |
| 정적만 | `python3 -m http.server 8137` | **빠짐** | 표시됨 |

`serve.py` 는 정적 파일 제공에 **뉴스 중계** 두 경로를 더한 것이다.

```
GET /                          정적 파일
GET /api/news                  RSS 5개 병합 · 5분 캐싱
GET /api/sentiment?coins=BTC,… 공포탐욕 + 트렌딩 + 종목별 투표 · 5분 캐싱
```

뉴스 RSS 는 어느 매체도 CORS 헤더를 주지 않아 브라우저가 직접 읽을 수 없다. 그래서 이
중계가 필요하다. 순수 정적 서버로 띄우면 두 요청이 404 가 되고, 화면은 **시장 심리
카테고리만 빠진 채 그대로 동작한다** — 뉴스 패널에 안내 문구가 뜬다.

## 3. 백그라운드로 띄우고 끄기

터미널을 닫아도 살아 있게 하려면:

```bash
cd /home/ec2-user/claude-lab/signal-desk
nohup python3 serve.py 8137 > /tmp/signal-desk.log 2>&1 &
```

**끄는 법.** 포트로 프로세스를 찾아 종료한다.

```bash
kill $(ss -ltnpH 'sport = :8137' | grep -oE 'pid=[0-9]+' | cut -d= -f2)
```

> `pkill -f serve.py` 는 쓰지 말 것. 이 패턴이 **자기 자신의 명령줄에도 걸려** 셸까지
> 죽는 일이 있다. 포트로 찾는 편이 안전하다.

**살아 있는지 확인:**

```bash
ss -ltnp 'sport = :8137'          # 리스닝 확인
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8137/index.html   # 200 이면 정상
curl -s http://localhost:8137/api/news | head -c 200                        # 뉴스 확인
tail -f /tmp/signal-desk.log                                                # 로그
```

## 4. 원격 서버에서 띄웠을 때 (SSH 터널)

이 서버는 외부에 포트를 열어두지 않는다. 로컬 PC 에서 터널을 뚫어 접속한다.

```bash
# 로컬 PC 에서 실행
ssh -N -L 8137:localhost:8137 <사용자>@<서버주소>
```

터널을 띄운 뒤 로컬 브라우저에서 `http://localhost:8137` 로 접속한다. `-N` 은 셸을 열지
않고 포워딩만 한다는 뜻이다.

터널이 자주 끊기면 유지 옵션을 준다.

```bash
ssh -N -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
    -L 8137:localhost:8137 <사용자>@<서버주소>
```

## 5. 재부팅 후에도 살아 있게 (systemd)

세션 종료·재부팅을 견뎌야 하면 사용자 단위 서비스로 등록한다.

```bash
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/signal-desk.service <<'UNIT'
[Unit]
Description=SIGNAL DESK
After=network-online.target

[Service]
WorkingDirectory=/home/ec2-user/claude-lab/signal-desk
ExecStart=/usr/bin/python3 serve.py 8137
Restart=always
RestartSec=3

[Install]
WantedBy=default.target
UNIT

systemctl --user daemon-reload
systemctl --user enable --now signal-desk
loginctl enable-linger "$USER"   # 로그아웃 후에도 유지
```

확인과 제어:

```bash
systemctl --user status signal-desk
journalctl --user -u signal-desk -f
systemctl --user restart signal-desk
systemctl --user stop signal-desk
```

## 6. 테스트 실행

서버와 무관하게 언제든 돌릴 수 있다.

```bash
node --test test/
```

지표·시그널·집계·어댑터·수급·심리·전환·탐욕지수를 검증한다. 어댑터 테스트는 고정
픽스처를 쓰므로 네트워크가 없어도 돌아가고, 연결이 되면 실응답 스모크까지 함께 돈다.

WebSocket 을 실제로 확인하려면 파이썬이 아니라 Node 쪽 플래그가 필요하다.

```bash
node --experimental-websocket <스크립트>   # Node 20 은 플래그로 전역 WebSocket 을 준다
```

## 7. 문제 해결

| 증상 | 원인과 처방 |
|---|---|
| `Address already in use` | 이미 8137 을 쓰는 프로세스가 있다. 3절의 `kill` 로 정리하거나 다른 포트를 쓴다 |
| 화면은 뜨는데 시세가 `—` | 거래소 WebSocket 이 브라우저에서 막힌 경우다. 헤더의 거래소 칩이 `폴링`·`중단`인지 확인한다 |
| 뉴스 패널에 안내 문구만 | `python3 -m http.server` 로 띄운 상태다. `serve.py` 로 다시 띄운다 |
| 뉴스가 일부 매체만 | `/api/news` 응답의 `failures` 를 본다. 한 매체가 죽어도 나머지는 나온다 |
| 코인원 지표가 `시세 전용` | 정상이다. 코인원 REST 는 CORS 를 주지 않아 캔들을 받을 수 없다 |
| 체결강도가 계속 `대기` | 60초 안에 체결 10건이 모이지 않은 것이다. 거래가 한산한 종목에서 정상이다 |
| 갱신이 느려짐 | 종목을 많이 담으면 크라켄 한도 때문에 캔들 한 바퀴가 길어진다. 상한은 6종목이다 |
| 탭을 다시 열었을 때 값이 낡음 | 탭이 숨겨진 동안 캔들 조회를 멈춘다. 돌아오면 즉시 한 번 받는다 |

---

## 8. 리소스를 아끼는 방법

헤더의 **일시정지** 버튼을 누르면 WebSocket 7본을 끊고 캔들 조회도 멈춘다. 화면의 값은
마지막 수신 시점 그대로 남는다. 다시 누르면 재연결하고 즉시 한 번 갱신한다.

탭을 다른 곳으로 옮기면 캔들 조회는 자동으로 멈춘다(소켓은 유지 — 끊으면 복귀할 때 7곳
재연결 지연이 생기고 체결 누적이 비어 체결강도가 표본 부족으로 떨어진다). 페이지를 떠날
때는 소켓을 정리한다.
